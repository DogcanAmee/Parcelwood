## 1. 一句话定位

> 每天早上一车包裹：**先看线索推理，再开箱确认**，把东西还给对的邻居，整条街会因为你慢慢变好。

- 推理是手感（独有，竞品里没有）。
- 邻居是回访理由（每天有具体的人在等你）。
- 收集和街道是长期目标。

不做：合并棋盘、体力条、全服排行榜、强制教程、红点任务雨。

## 2. 诊断（v1 现状，依据 `src/core/config.ts`、`README.md`）

| 问题 | 证据 | 后果 |
|---|---|---|
| 系统多、内容少 | 13 项玩法；3 个系列 × 8 件 = 24 件物品；5 位居民各 3 段故事 | 像在做杂事，不像在生活 |
| 数值太多 | 金币、碎片、宝石、口碑、爱心、公告章、账本印记、急件星级 | 玩家说不清在追什么 |
| 长线太短 | 估算每天约 50 口碑，Lv5 = 280，约 6 天满级（估算，非实测） | 满级后只剩补 24 件图鉴 |
| 核心手感错位 | 猜测只是 +2/+3 ✨ 的附加项，主体是带保底的抽盒 | 像普通抽卡；Discord 审核风险（`ship-plan.md` B22） |
| 社交缺席 | 只有每日之谜可复制成绩 | Discord 版的优势没用上 |

## 3. 核心循环（每天 5–8 分钟）

1. **早班车**：一批包裹，每个有声音、重量、邮戳、面单线索。
2. **推理**：先猜是谁的、里面是什么，再决定拆开还是送还。X 光是推理工具，不是跳过推理。
3. **确认**：猜对拿更多；猜错不惩罚，只是邻居的反应不同。
4. **邻居反应**：每次拆开或送还，都有一位邻居说一句和当天有关的话。
5. **街道变化**：口碑直接变成看得见的修复（路灯、长椅、新店、新邻居）。

## 4. 系统收拢

| 现有系统 | 处理 |
|---|---|
| 拆包 + 猜系列/稀有度 | 改成主玩法：先推理再开箱 |
| 每日之谜 | 放到首页最显眼的位置，带不剧透分享 |
| 居民委托 + 公告板 | 合并成“今日来信” |
| 送礼 + 爱心 + 故事 | 保留，改成每次开箱都有小推进 |
| 错寄件 + 无名件 + 加急件 | 统一成推理难度：普通 → 加急 → 无名 |
| 每日事件 | 保留（本质是改变线索） |
| 小镇 5 级 | 保留为功能/邻居解锁；新增“修复包裹街”作为满级后的长线（第一批 6 栋楼 × 4 处可见改造，见第 11 节） |
| 急件高峰 | 降为可选小游戏，不再是主线解锁 |
| 驿站一周 | 不再冻结：改为每周活动。每天都能玩；周五到周日完成/通关/三星各领一次金币和碎片；同一周所有人同一份班表；所有版本都能玩 |
| 8 种数值 | 收成 3 个主数值：金币（花）、爱心（关系）、街道进度（长线） |

### 4b. 驿站一周：每周活动（2026-11-05 董事会决定）

- **不再冻结，也不再删掉。** 网页、Discord、CrazyGames 三个版本都能玩，等级门槛仍是 Lv4，仍然按需加载，不增加首屏下载。
- **每天都能玩，只有周末发活动奖励。** 活动时间是玩家本地时间周五 00:00 到周日 24:00。三档奖励每档每周只发一次，直接进主游戏：完成一周 +30 金币；赢下这一周再 +30 金币、+10 碎片；三星再 +20 碎片。数字在 `src/core/config.ts`。平日玩只算练手，不扣任何东西。
- **同一周，所有人同一份班表。** 开局种子由这一周（周一到周日）决定，所以同一周每个人第 1 天的包裹、订单和事件都一样。卡片上写出本周主题。
- **成绩可复制分享。** 一行字，包含周次、星级和卖出件数，不剧透班表，也不上传到任何地方。分享地址只带页面本身，去掉 `devlv`、`devday`、`ads` 等预览/本机参数，收件人打开的是干净的游戏地址。
- **原来的账本印记和升级保留**，仍然只在驿站一周里用，不新增主游戏货币。

#### 4b-1. 时钟保护与残留风险（TAO-86）

- **网页版不只看手机时间。** 启动时向同一个静态站点发一次 `HEAD` 请求，用响应里的 `Date` 头做锚点，之后用 `performance.now()` 单调计时。这样在本次会话里改手机时间不会让周五提前到来；同步成功后周末卡片会重绘。
- **存档记一个已见时间的最高值。** 每次收工结算都会保存见过的最晚时间。如果设备时间退回到这个值之前（超过 5 分钟容差），周末奖励暂时关闭，直到时间追上；所以先往前改、再改回来，不能把已经领过的过去一周再领一次。
- **残留风险。** 离线、静态站点不返回 `Date` 头，或 Discord/CrazyGames 等宿主版本没有可信时钟时，只能退回设备时钟。此时刻意把时间往前跳到未来某个周末，仍可能提前领到那一周的奖励；我们只保证同一次“往前再改回”不会重复领取，也没有服务器可以做权威校验。直接改存档文件同样不在防护范围内。

## 13. 第 1b 步：今日来信（规则合并，2026-11-04）

**做法**
- 信 = `state.board.tasks`，每天 3 封。`state.requests` 从 `GameState` 删除；`src/core/requests.ts` 只保留谜语生成（`makeRequest`）、`spares` 和交付结算 `handOver`。
- 从 Lv2 起，最多 2 封是“心愿信”（`kind: 'wish'`，带 `clues`），至少留 1 封小事。心愿用重复物品回答：交对当场发 40 🪙、回收值 + 3 ✨、1 颗心和口碑，信标记完成；不再额外发小事的 +20 🪙（不重复发奖）。交错不扣任何东西，信留着。
- 三封都完成（无论最后一封是小事还是心愿）给公告章 + 15 ✨ + 5 口碑（`stampIfFull`）。
- 当天升到 Lv2：没动过的小事换成心愿（`addWishes`，启动/读云存档/升级时都会调用，已有心愿则不动）。
- 界面：小镇页信件板的心愿信显示线索图标 + 🎁“交一件重复的”按钮；街道房顶气泡读同一份信；帮助文案、升级列表改叫“心愿信”。

**存档迁移**（`src/core/sanitize.ts`）
- 带旧 `requests` 字段的存档：丢弃 `requests`，把当天的公告板日期清空、从 `board.made` 去掉，下次刷新先结算旧板上已完成未领的小事，再贴新的 3 封信。
- `board.tasks` 校验：心愿必须有合法线索、`arg` 为 null；小事不能带 `clues`；只对小事去重；心愿最多 `requestsPerDay` 封。旧的 `request` 类型仍可读。

**验证**：`npx vitest run` 42 个文件 311 项通过（重写 `tests/requests.test.ts`，更新 board/account/town/sanitize 测试，新增迁移、升级换信、最后一封是心愿也给章等用例）；`npm run typecheck`、`typecheck:discord`、`build`、`build:crazygames`、`build:discord` 通过。本地浏览器（420×900，中文，Lv3 存档）：3 封信里 2 封心愿 + 1 封小事，交错 3 次不扣物品，交对 +40 🪙、物品 3→2、解锁新故事。

## 15. 第 3 步：Discord 社交——捎带包裹 + 服务器周榜（2026-11-04）

只在 Discord 版出现（`backend.social`）；网页版和 CrazyGames 没有这个面板。小镇页右栏、包裹街和小镇等级之间多一张 🤝 卡片，只用图标和数字，文字都在 `.sr`。

**捎带包裹**（`src/core/social.ts`、`src/discord/social.ts`）
- 当天三封来信全部完成（最后一封小事领取或心愿交付）→ 得到 1 个可捎带的包裹；每天最多 1 个，没送出不叠加。
- 点「📦 → 🧑‍🤝‍🧑」：服务器发一次性 token（`carry_send`，每人每天最多 3 个，取消分享可以重试），用 Discord `shareLink` 分享 Activity 链接，token 放在 `custom_id`。分享或复制链接后算送出。
- 好友从链接打开 Activity：`carry_claim` 只成功一次 → 货架 +1 普通包裹、+15 ✨。自己打开自己的链接提示“发给好友”；已用、过期（14 天）或当天已收 3 个 → 提示已被打开。本机记住已兑换的 token，避免重复提示。
- 发送者下次打开（或 30 秒后回到小镇页）时，`carry_thanks` 返回新被打开的个数，每个 +15 ✨，服务器标记后不会重复发。

**服务器周榜**
- 每完成一封来信，向当前 Discord 服务器（`guild_id`）本周（周一起）总数 +1；每人每周最多计 21 封，单人刷不满。
- 目标 20 / 60 / 150 封，每达成一档，本周至少贡献 1 封的人各得 +20 ✨（存档记 `guildWeek` / `guildPaid`，每档每周只发一次）。私信 / 群聊里没有 guild，不显示周榜。
