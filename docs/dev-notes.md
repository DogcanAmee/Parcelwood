# 开发笔记（存档）

这是 Parcelwood 暂停前的原 README，记录了各个版本、玩法规则、后端和上线计划的细节。项目已暂停，这里的内容不再更新；其中提到的 Supabase 项目、Discord Activity 和线上部署都已下线。

网页版先上，之后用 Capacitor 打包成 iOS / Android。TypeScript + Vite，没有框架。

## 本地运行

```
npm install
npm run dev      # 开发版：有开发者面板，登录用本地模拟
npm test         # 抽奖/保底、年龄门槛、存档同步、登录页、小镇等级、急件高峰、整局冒烟测试
npm run typecheck
npm run build    # 正式包，输出到 dist/
```

新玩家第一次进入不再弹大窗：货架上直接有手指和短图标提示，依次是点包裹 → 用一个线索 → 选系列（可跳过）→ 划胶带 → 揭晓，右上角常驻 `Skip`，桌面端还会显示鼠标/键盘提示。第一次揭晓前，Lv1 首屏只显示货架、货币和一个当前目标；保底条、店铺、小镇等级、签到和每日任务在第一次揭晓后（或 Lv2）出现，旧存档直接显示全部。之后点右上角 `?` 或拆包页的 `?` 可以重看。

## 声音与图标

- 背景音乐是运行时合成的原创循环（66 BPM，29 秒，无缝），不占包体。音效也是合成的；全部走同一条低通 + 压缩总线，高频不刺耳。授权和播放规则见 `docs/audio-credits.md`。
- 音乐只在第一次点击/按键后开始（iOS 要求），跟随游戏内静音按钮和 CrazyGames SDK 的 `muteAudio`。
- 界面里的系统 emoji 会在渲染后换成手绘图标（`public/icons/*.webp` + `*.svg`）。`tests/no-emoji.test.ts` 会拦住漏配图标的新 emoji；图标说明见 `docs/art-bible.md` 第 7.1 节。

## CrazyGames 广告版

和网页版同一套游戏代码，单独的入口和构建，互不影响。

```
npm run dev:crazygames             # 本地跑，地址是 localhost，SDK 自动进 local 模式（广告位只显示一段提示文字）
npm run build:crazygames           # 交给 CrazyGames 的包，输出到 dist-crazygames/，把里面的文件打成 zip 上传
npm run build:crazygames:preview   # 测试包：不加载 SDK，用 5 秒的模拟广告，底部有“测试版”横条。不要上传这个
npm run check:release              # 构建完两个上传包后跑一遍：确认里面没有网页版专属代码和开发面板
```

- 代码在 `src/crazygames/`（SDK 封装、广告、存档、入口），字体统一在 `src/fonts.ts`，页面在 `crazygames/index.html`，构建配置是 `vite.crazygames.config.ts`，设置在 `src/crazygames/config.ts`。
- 这一版是全年龄（Tao 10 月 31 日定的）：一进来就能玩，没有年龄页，不登录，不存任何个人信息，不卖东西，没有任何外链（社区 Discord 链接也不放，Discord 只给 13 岁以上）。除了 CrazyGames 的 SDK，不向任何服务器发请求：不连我们的后端，字体也打包在里面，不从 Google Fonts 加载。网站、Discord、App 版本还是 13+，年龄页逻辑没动，只是这个构建里 `ageGate: false`。
- 广告的儿童合规由 CrazyGames 负责：SDK 没有给开发者的儿童或非个性化广告开关；它的主站是 13 岁以上，儿童站是另选的、广告关闭（SDK 会返回 `adsDisabled`，游戏自动只剩金币兑换）。提交时别把游戏写成“面向儿童”，CrazyGames 初审会以 “Content is targeted for kids” 拒掉。
- 跟网页版的区别：没有商店里的付费项目、没有宝石、没有自己的登录和账号页、没有 Stripe、不注册 service worker。商店页变成“免费奖励”：看一段激励广告或者花金币，换“提前送货”（最多 3 个包裹，到货架满为止）或“失物加急”（1 个错寄包裹）。规则在 `src/core/ads.ts`：两次激励广告至少隔 3 分钟，每天最多 8 次，按钮上有倒计时（把系统时间往回调不能重置次数）；广告看完才发奖励。每开 3 个包裹、并且这一局玩满 3 分钟后，点“下一个包裹”时请求一次插屏广告（不在返回、导航按钮上放；刚集齐一个系列时跳过；SDK 自己还会再限频）。
- 存档走 SDK 的 Data 模块（跟着玩家的 CrazyGames 账号走）。同一个浏览器第一次用时，把浏览器里已有的存档搬进第一个还没有存档的账号，搬完删掉浏览器里那份（换个账号是全新存档；账号已有存档时浏览器那份原样保留，留给第一个还没有存档的账号）。两边的存档从不合并，所以旧副本永远不会盖掉账号进度；代价是某一局 SDK 被拦截或太慢、只能存在浏览器里时，那一局的进度留在浏览器里，不会搬进账号。提交时要选“Yes, using the Data Module”，否则一直用浏览器存储。
- 有广告拦截、广告关闭（Basic Launch 阶段、儿童模式）或者没填充时，看广告按钮隐藏或不发奖励，金币兑换照常能用，游戏完全能玩。开局前先查一次广告拦截（最多等 1.5 秒）。
- 概率公示（商店页和小站页的“概率”按钮）、保底、三语都保留。语言优先用 CrazyGames 给的地区语言。
- 小镇等级、居民委托、加急件、每日事件和无名件在这个版本同样生效；急件高峰在网页、Discord 和 CrazyGames 三个构建都能玩。

> 玩法方向和分步改版计划见 `docs/design-v2.md`。第 1 步已实现：先推理再开箱、驿站页顶部的今日之谜、“今日来信”（公告板 + 居民委托）、开箱后邻居说一句话。第 2 步已实现：包裹街（口碑修好 6 栋楼的 24 处改造，满级后的长线目标）。第一阶段 M2 已实现：猜系列连胜（猜中加金币、猜错清零、邻居在里程碑说一句）、车站装饰店（10 件现有物品图的展示模型，金币购买，可摆出或收起，刷新后保留）。玩法指标（先猜再拆比例、每日之谜完成率等）存在存档里，说明和查询见 `docs/metrics.md`。

- `node qa/m1-mobile.mjs` 用 iPhone / 安卓尺寸跑一遍并输出截图（先在 `qa/` 里 `npm install`）。
- 前 3 分钟不出插屏的规则在 `src/core/ads.ts` 的 `AD_RULES.midgameFirstAfterMs`；界面在「下一个包裹」处统一判断。

## 小镇成长（等级、居民与新快递）

小镇有 5 级，口碑攒够就升级。每个等级带来新邻居、新玩法或新系列，让"每天来拆快递"逐步变成"经营一条有人的街"。

设计上刻意让每一级都有"下一站"：新邻居会说话、会提要求，新包裹类型会改变当天怎么玩，而不是只把同一件事的奖励调高。所有限时和猜谜都不做惩罚式失败——加急件超时、无名件猜错都还能继续，损失只是少拿奖励。

| 等级 | 解锁 | 说明 |
| --- | --- | --- |
| Lv1 | Okafor 太太、Theo | 正常拆包裹 |
| Lv2 | Dube 先生、居民委托、急件高峰 | 邻居每天请你找东西；导航出现"急件高峰" |
| Lv3 | 加急件、每日小镇事件 | 早班车多一件限时件；每天有一个全局事件 |
| Lv4 | Lena | 自行车店邻居搬来 |
| Lv5 | 双胞胎、无名件、城市纪念品系列 | 面单没有名字的包裹；第三个系列开始掉落 |

### 口碑

- 拆包裹 +1，猜对系列/稀有度各 +1，送还错寄件 +5，完成委托 +6，送礼 +2（送中心头好 +4），每日之谜 +4（没猜中 +2），加急件按时 +6，集齐系列 +20，急件高峰正式轮班 +5。
- 门槛在 `CONFIG.townLevels`，默认 `[0, 30, 80, 160, 280]`。
- 升级后会在没有弹窗、没有拆包界面时集中弹出一次升级提示，列出新邻居、新玩法和新系列。
- 旧存档没有等级数据时，按已拆数量、猜中次数、送还数、爱心、已集齐系列、玩过的每日/急件高峰次数折算口碑，并直接定到对应等级，不会连续弹升级。

### 居民、委托与送礼

- 委托从 Lv2 开始，每天 2 个，只由已经搬来的邻居发布。线索、奖励、爱心和故事规则不变：40 金币 + 1 颗心 + 比回收多 3 个碎片，交错不扣东西。
- 每位邻居有一个"最爱的东西"（按声音区分，例如 Theo 喜欢会"咚"一声的东西）。小镇页显示邻居的特点、当前状态和最爱礼物；没摸清之前显示"还没摸清"。
- 送礼每天每位邻居一次，只能送重复件。普通礼物 +1 心，送中最爱 +2 心，并永久记下这个邻居的最爱。
- 好感 3 颗心解锁实际福利：
  - Theo：每天早班车多给 15 金币。
  - Dube 先生：每天第一次 X 光免费。
  - Lena：错寄件从每 2 小时一个改为每 90 分钟一个。
- 1/3/6 颗心的三段故事仍然保留。

### 加急件（Lv3）

- 每天早上随货车来一件，4 小时内送到有额外 25 金币和一颗心；超时仍可送还，只是没有加成，不惩罚。
- 加急件属于某位居民，只能送还，不能拆开。货架上显示倒计时，超时显示"已超时"。
- 同时在场的加急件最多 2 件；它们不占失物箱的 3 个位置。

### 每日小镇事件（Lv3）

按日期算出，同一天所有玩家一样，不用服务器。每天一个：

- 下雨：早上大部分包裹的邮戳会被晕开；猜对系列碎片翻倍。
- 停电：X 光机停用；猜对稀有度碎片翻倍；Lv5 起无名件更容易出现。
- 搬家日：早上多来一个错寄件；当天每次送还额外 +10 金币。

事件卡显示在车站页和小镇页顶部，数值在 `CONFIG` 的 `anonChance`、`anonChancePowercut`、`movingBonus`。

### 无名件（Lv5）

- 面单上没有名字，只有一条线索（例如"已分拣：31 号线"）。用"看看"读取线索，再到小镇页对照邻居的特点和最爱礼物判断是谁的。
- 猜错不扣东西、包裹保留；一次猜对额外 +20 金币。也可以直接拆开，但拆开就失去送还的奖励。
- 无名件和普通错寄件共用失物箱，失物箱上限仍是 3 个。

### 每日之谜

- 按当天日期算出谜题，同一天所有人一样，不用服务器。题库是开局两个系列的 16 件。线索依次是声音、重量、邮戳，最多猜 3 次，奖励固定碎片（12/8/4，没猜中 2），不给物品。可以复制一段不剧透的成绩。

### 系列解锁

集齐系列仍然发 300 金币和 20 口碑，但**不再自动解锁下一个系列**。第三个系列"城市纪念品"改为 Lv5 开放，这样等级是明确的进度线。相关规则在 `src/core/town.ts` 的 `syncUnlocks` / `claimLevelUp`。

数值都在 `src/core/config.ts`（`townLevels`、`townFeatures`、`seriesLevels`、`rep`、`urgentMs`、`urgentBonus`、`anonBonus`、`anonChance`、`movingBonus`、`perkHearts`、`theoCoins`、`lenaMysteryMs`）。存档新增 `state.town = { rep, level, gifts, known, xrayDay }`；旧存档缺 `town`、包裹缺 `urgent`/`anon`/`misses` 时由 `src/core/sanitize.ts` 补默认值或拒绝非法值。

## 急件高峰（所有构建，Lv2 开放）

每天一轮 90 秒的分拣挑战，和每日之谜一样按日期生成，同一天所有玩家面对同样的包裹、超大件和工具选项。

- 第一个开始的轮班是当天的**正式轮班**：记录成绩、发碎片（按星级 2/5/8/12），并加 5 口碑。同一天再玩是练习，不重复发碎片；练习每星给 5 金币，每天最多 3 次有金币的练习班。
- 传送带会送来普通包裹和错寄件。错寄件需要用"退回"（键 4 或 Backspace）送回；猜错只断连击、不加分，不会直接扣命。真正扣"失误"的是传送带漏件，3 次漏件结束。
- 每天的超大件里有一件当天的限定纪念品（共 7 件），拆开就永久收进图鉴的"急件高峰"页。
- 工具升级、暂停、结算和分享文案都在 `src/rush/`；规则和每日种子在 `src/core/rushHour.ts`，存档字段是 `state.rush`。
- 网页、Discord 和 CrazyGames 三个构建都有，小镇 Lv2 开放。货架空时，小站直接显示"玩急件高峰"按钮；Lv1 显示还差多少口碑。`src/rush/` 是懒加载 chunk，不增加首屏体积。驿站一周仍然只在网页版、Lv4 开放。

## 每日任务与打卡

- 小站货架下方新增"今天"面板：固定 3 个每日任务（猜对 2 次、送回 1 件错寄件、完成每日包裹；Lv2 后第三项换成玩 1 次急件高峰），每个奖励 25 金币 + 2 口碑；三项都领取后额外给 20 碎片和 1 件错寄件。
- 前一天完成但没点领取的任务会在新一天自动发放，不会丢失。
- 打卡卡每天可盖 1 个章，每次 +10 金币；漏一天不会清空。第 5 个章触发"大丰收"：再 +10 金币、货架多 5 件包裹、+50 碎片，然后卡片重新从 0 开始。
- 规则在 `src/core/quests.ts` 和 `src/core/checkin.ts`，存档字段是 `state.quests` 和 `state.checkin`。

## 驿站一周（网页版，Lv4 开放）

后仓的五天经营模式，和主界面的收藏、急件高峰并存，但产出完全分开。

- 每天第一次收工得**账本印记**：收工 1 枚，通关 +1，三星 +1（每天最多 3 枚）。同一天再玩是练习，不给印记。
- 印记只进**后仓账本**，升级只影响这一模式：多一双手（+1 行动点，之后 +20 开局金币）、加一层架（最多 +2 仓储）、熟能生巧（每天 1 次免费普通检查，之后邮戳不再模糊）。
- 账本等级存 `state.week.levels`；进行中的一局只存 `seed + log + 开局 mods`，回放能复现同一局。旧存档没有 `marks`/`levels` 时补零。
- 这一模式不产出金币、碎片、口碑或物品，避免和主循环、急件高峰的奖励重叠；主界面的入口卡会显示当前印记数。

## 登录怎么工作

1. 第一次打开先过年龄页（选出生年月）。只存"通过/没通过"，不存生日。没通过的处理方式见 `src/core/age.ts` 里的 `UNDER_AGE_POLICY`。
2. 通过后自动建一个游客账号（Supabase 匿名账号），进度存本机，同时传到云端。
3. 账号页可以用 Apple、Google 或邮箱链接登录。新地址直接把游客账号升级成正式账号，进度不丢；已有账号就切过去，两边都有进度时让玩家选保留哪份，游客的宝石带过去。
   宝石余额以服务器为准（`0003`）。换到另一个已有账号时，游客的余额由 `0004` 的票据在服务器上转过去（见下面的“宝石余额和退款”），客户端不再自己相加。
4. 退出登录或删除账号后，这台设备开一局新的游客游戏。删除账号会删掉云端存档（苹果要求能在应用里删账号）。

## 接真实 Supabase（需要先开账号，还没做）

1. 建 Supabase 项目，把 `.env.example` 复制成 `.env.local`，填项目地址和 publishable key。
2. Authentication 里打开：Anonymous sign-ins、Manual linking、Email（magic link）、Apple、Google；把网页地址加进 Redirect URLs。只写完整地址（如 https://parcelwood.app/），不要用 `**` 通配符，否则别的网站也能接到登录跳转。登录已用 PKCE：邮件链接只能在发起登录的那个浏览器里打开。
   同时给匿名登录开 CAPTCHA（Supabase 支持 hCaptcha / Turnstile），防止有人批量刷游客账号。再加一个定时任务，删掉 30 天没登录、也没升级成正式账号的游客账号（官方建议做法）。
3. 按顺序跑 `supabase/migrations/` 里的 0001、0002、0003、0004，部署 `supabase/functions/delete-account`，设 `ALLOWED_ORIGIN`。

## 宝石余额和退款（0003）

- 余额在服务器的 `wallets` 表，每次变化都在 `gem_ledger` 记一行；同一笔订单、退款或花费只能记一次。
- 订单写进 `discord_orders` / `web_orders` 时自动入账；订单标成退款（`refund_order`，或网页订单把 `status` 改成 `refunded`）时自动扣回。已经花掉的宝石被退款时余额会变负，游戏里显示 0，补足之前不能再花。
- `push_save` 不再相信上传的宝石数，存进去的永远是服务器余额。以后卖“10 个额外包裹”时，用 `spend_gems(数量, 这次花费的 id)` 在服务器扣。
- 游客余额并入（0004）：游客账号换到另一个已有账号时，客户端先向游客账号要一张一次性票据（`issue_guest_ticket`），登录后由账号调用 `claim_guest_ticket` 在服务器上把余额转过去；重复兑换、过期票据、已被升级的游客都不会二次转账。票据存在本机 `parcelwood.guestTicket`，网络失败会留到下次登录再试。
- Discord 退款：`discord-webhook` 收到 `ENTITLEMENT_DELETE` 立刻退；`discord-claim` 每次也会检查已删除的购买，作为兜底。网页（Stripe）退款等接 Stripe 时，在 webhook 里调用 `refund_order('web', 订单 id)`。
4. Apple 登录需要 Apple Developer 账号（$99/年）里的 Services ID 和密钥；Google 登录需要 Google Cloud 的 OAuth client。

## 做手机版（P3）前必须补的

- 删除用 Sign in with Apple 登录的账号时，要撤销 Apple 的 token（苹果规定）。`supabase/functions/delete-account` 里留了位置，要 Apple 密钥。
- Google 不允许在 App 内嵌网页里登录。手机版的 Apple / Google 登录改用原生登录或系统浏览器，回跳用 App 自己的链接，不能用网页地址。
- Google Play 要求提供一个网页，让玩家不装 App 也能申请删除账号。
- 每天的货架补货（`deliver`）也记住了最近 60 个送货日，时间来回调不会重复补货。但设备时钟仍是客户端数据，不能当成服务器时间；真正严格的每日限制仍需要服务端时间。
- 网页版同一时间只允许一个标签页玩并存档（Web Locks，见 `src/ui/tabGuard.ts`）；不支持 Web Locks 的旧浏览器仍会两边同时写。

## 安全上线前检查

- 生产环境不要设 `VITE_DEVTOOLS=1`（Vercel production 构建会直接报错）。
- 存档无论来自云端还是本机，都先过 `src/core/sanitize.ts` 检查，格式不对就不用。
- `vercel.json` 带 CSP；以后加新的外部服务（Stripe、广告）要把域名加进去。
