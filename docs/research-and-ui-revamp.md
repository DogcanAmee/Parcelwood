# Parcelwood: 竞品调研与界面改版（2026-11-02）

## 1. 调研方法与边界

- 日期：2026-11-02。方法：网页检索，优先取开发者访谈、Steam 官方商店页、维基/媒体报道；只记录能在来源里找到的事实。
- **已核实**：Unpacking、Good Pizza, Great Pizza、Wilmot's Warehouse、Pokémon TCG Pocket。
- **本轮未核实**：Pokebonk、Animal Crossing、Stardew Valley、Papers, Please。它们只在候选清单里，下面不下结论，下一轮补。
- 来源多为二手（媒体、维基、社区），Steam 页面只覆盖 Wilmot's Warehouse；数字（下载量、评分）不当作决策依据。

## 2. 竞品对比（只含已核实内容）

| 产品 | 核心循环 | 回流/进度 | 对 Parcelwood 的启示 |
|---|---|---|---|
| Unpacking（Witch Beam，2021） | 从纸箱里取物、放进房间；物品本身讲故事，几乎没有文字。[Game Developer](https://www.gamedeveloper.com/marketing/unpacking-a-narrative-through-1-000-household-items)、[Wikipedia](https://en.wikipedia.org/wiki/Unpacking_(video_game)) | 8 个年代的房子线性推进；团队刻意不做分支叙事，避免 FOMO 和“选错”的压力。 | 开箱的乐趣在“物件有人味”。每件物品要有归属和故事，惩罚机制要克制。声音也是卖点（每件物品有独立拾取/放置音效，见 Wikipedia）。 |
| Good Pizza, Great Pizza（TapBlaze） | 接单 → 按描述做出来 → 赚钱升级设备/装饰。100+ 位性格各异的顾客，剧情随订单展开。[Wikipedia](https://en.wikipedia.org/wiki/Good_Pizza,_Great_Pizza) | 设备升级、装饰、赛季活动。 | 常客是留存的核心：让居民在每天的包裹里“出场”。反例：Steam 评论吐槽循环重复、升级过贵，说明只有换皮内容不够。 |
| Wilmot's Warehouse（Finji，2019） | 收货整理阶段 → 窗口开放后凭记忆取货交付；按速度得星，换升级。[Steam](https://store.steampowered.com/app/839870/Wilmot's_Warehouse/)、[Wikipedia](https://en.wikipedia.org/wiki/Wilmot's_Warehouse) | 每月结算星星换升级；物品种类越来越多，仓库越来越挤。 | “先整理、后取用”的两段式节奏，给了包裹站一个可做的“路线/分拣”玩法；难度来自玩家自己的整理方式，而不是惩罚。 |
| Pokémon TCG Pocket | 每日开包 + Wonder Pick（从其他玩家的包里挑一张）。有等级系统、体力恢复、每日礼物。[Nintendo Wire](https://nintendowire.com/guides/pokemon-tcg-pocket/introduction/)、[GamesRadar](https://www.gamesradar.com/games/pokemon/pokemon-tcg-pocket-wonder-pick/) | 体力随时间恢复，每日任务/礼物/升级给沙漏。 | 每日开包本身不够，它靠“第二个动作”（Wonder Pick）和等级解锁补足。同时社区有明显负面反馈（觉得挑选没有真实影响，来源：[TheGamer](https://www.thegamer.com/i-dont-mean-to-be-dramatic-but-pokemon-tcg-pockets-wonder-pick-makes-me-wish-i-were-dead/)）——假选择会伤口碑，Parcelwood 的选择必须真的影响结果。 |

## 3. 取舍

**借鉴**
- 物品和居民的故事感（Unpacking、Good Pizza）。
- “整理后取用”的节奏（Wilmot）。
- 每日回流要有第二个动作和等级解锁（TCG Pocket）。

**避免**
- 分支叙事和限时惩罚（Unpacking 的明确设计选择）。
- 只换皮的内容更新、过贵的升级（Good Pizza 的 Steam 差评）。
- 看起来能选、实际不影响结果的“假选择”。

**Parcelwood 的现状**：已有小镇等级、居民、错投包裹、Rush Hour。缺的是“每天打开游戏的具体理由”和“让居民在包裹里出场”。

## 4. 玩法优先级

1. **每日小镇任务板**：已实现，见第 9 节。
2. **路线模式**：把匿名/紧急包裹串成 3–5 件的投递路线（借鉴 Wilmot 的两段式）。
3. **居民故事链**：同一居民连续几天的包裹串成短故事（借鉴 Unpacking/Good Pizza）。
4. 小镇建设可视化、包裹属性与工具取舍、陈列馆藏。

建议先做 1，再做 2。不要同时大改多个页面。

## 5. 当前界面诊断（改版前）

- 灰底白色圆角卡片堆叠，像后台表单；没有场景层次、材质、光照。
- 页面切换、顶栏、导航基本静态。
- 开箱只是整个箱子缩小淡出，没有“开盖”。

## 6. 视觉方向与动画（已实现，见 `src/styles.css` 末尾“Visual layer”）

方向：把“一叠卡片”换成“有生命的邮局场景”——牛皮纸、木头、黄铜、墨线描边、纸张颗粒。

- **驿站立面**（`stationView()`）：天空、云漂移、太阳呼吸、会轻晃的木招牌、条纹遮阳棚、闪烁的灯。
- **货架**：包裹放在木板上，带落地阴影；神秘包裹轻微上下浮动，紧急包裹周期性抖动；悬停抬起，按下压扁。
- **页面进入**：顶栏下落、面板依次弹入、包裹逐个落到货架上（延迟按序号错开）。
- **开箱演出**：箱子悬浮 + 地面阴影呼吸 → 胶带被撕飞 → 箱体压扁回弹 → 两片盖子向外翻开 → 光柱（按稀有度变色）→ 稀有以上粒子爆发 → 结果页光芒旋转、元素依次出现、“NEW”章盖下。
- **反馈**：金币/星屑增加时胶囊弹跳；按钮有厚度与按压感；底部导航是木条，当前页图标跳起。
- 深色模式换成夜景（暗天空、点亮的灯）。
- `prefers-reduced-motion` 沿用原有全局规则，并且代码里开箱走无延迟路径。
- 没有新增依赖和外部图片，全部是 CSS 和少量标记（`app.ts`）。

## 9. 每日小镇任务板（已实现）

**规则**（`src/core/board.ts`，数值在 `CONFIG.board`）
- 每天第一次进游戏时，由已入住的居民贴出 3 张纸条，种类互不相同：至少 1 张柜台类（拆 3 个、猜对 2 次、拆出某种声音、拆 2 个某系列），至少 1 张小镇类（送还错寄件、送礼、每日神秘包裹、居民委托、高峰时刻）。
- 只贴当天做得到的：没有多余副本不贴“送礼”，Lv2 前不贴“委托”，Lv4 前不贴“高峰时刻”，今天玩过每日包裹就不贴“每日包裹”；“声音”只选已解锁系列里普通品会发出的声音。
- 进度在对应操作成功后自动累计；完成后点“领取”：+20 🪙、口碑 +3。三张都领：+15 ✨、口碑 +5、公告章 +1（累计显示）。
- 不惩罚：没做完的纸条第二天直接撤下；做完但没领的，换新板时自动补发（全部做完的话也补公告章）。
- 防调钟：和委托一样记住最近贴过板的日期，往回调时钟不会重贴；昨天打开的领取按钮点了只提示“公告板已经换新了”。
- 存档：新增 `board` 字段，旧存档自动补空板；`sanitize.ts` 严格校验种类、居民、进度上限、已领必须已完成、不能重复种类，多余字段丢弃。

**界面**
- 小镇页最上方：软木板 + 木框，纸条用图钉钉住、略微歪斜；进入页面时纸条依次“钉上”。完成的纸条轻轻摆动、领取按钮呼吸发光；领取时纸条抖一下、红色“已盖章”印章砸下去，标题划线。
- 底部三枚印章位依次点亮，全部完成时奖励条变成金色。
- 货架页小镇条里有一行公告板进度（三个圆点，可领取时显示“N 件可领取”）；底部“小镇”按钮在有可领取奖励时显示跳动的红色数字角标。

**验证**
- `tests/board.test.ts`（10 项）：贴板规则、防调钟、可行性过滤、计数、领取与公告章、跨天补发、存档校验、三语文本。
- `tests/board.ui.test.ts`（5 项，jsdom）：货架进度、角标、在小镇页送礼完成纸条、领取加金币、最后一张盖公告章、过期按钮无效。
- 浏览器（390×844、1440×900、中文）截图检查了纸条、领取盖章、角标，无横向溢出。
- 尚未验证：真实玩家是否因此在同一天多开一次包（需要上线后看数据）；高峰时刻纸条只在核心测试里覆盖，没在浏览器里实际跑一班。
